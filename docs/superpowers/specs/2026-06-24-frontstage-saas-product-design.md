# FF-CompanyBrain 前台 SaaS 级产品形态设计

日期：2026-06-24

## 1. 设计目标

把前台从“功能堆叠型 demo”重构为一个正式 SaaS 级产品前台。用户进入后先看到清晰、克制、可信的“问公司大脑”入口；当用户需要构建特定知识能力时，再通过场景模板创建可用场景。

核心判断：

- 首页只承担一个动作：问公司大脑。
- 场景模板是业务能力包，不是简单卡片。
- 我的场景是模板实例化后的可用知识应用。
- 任务中心承接上传、处理、审核、失败重试、就绪提醒和成品生成。
- 知识空间承接已处理完成的可浏览知识结果。
- 前台永远不暴露 `chunk / embedding / LightRAG / GraphRAG / entity extraction` 等技术词。

## 2. 固定前台导航

顶部导航固定为五项：

| 导航 | 用户理解 | 实际职责 |
|---|---|---|
| 问公司大脑 | 我直接问公司问题 | 全局问答入口，自动使用用户有权限的已就绪场景和知识来源 |
| 场景模板 | 我想创建一种知识能力 | 官方模板库，说明适用情况、输入数据、输出效果和创建流程 |
| 我的场景 | 我已经创建好的知识应用 | 用户或团队从模板生成的场景实例，可问答、浏览、管理、分享 |
| 任务中心 | 我上传的资料处理到哪了 | 建库任务、生成任务、审核任务、失败重试、就绪提醒 |
| 知识空间 | 我能浏览哪些知识结果 | Wiki 条目、文档证据、关系结果、成品归档和来源浏览 |

导航顺序不可随意改变。首页不再承载任务卡片或场景卡片；这些能力只从导航或 Chat 动作进入。

## 3. 产品对象模型

### 3.1 场景模板

场景模板是官方预置能力包。它必须回答五个业务问题：

- 这个模板适用于什么情况？
- 用户需要提供什么数据？
- 系统会把这些数据整理成什么知识能力？
- 处理完成后，用户可以怎么使用？
- 用户能得到什么业务结果？

模板字段：

| 字段 | 前台展示 | 说明 |
|---|---|---|
| 名称 | 是 | 业务名称，如“个人知识 Wiki” |
| 一句话说明 | 是 | 直接说结果，不说技术 |
| 适用情况 | 是 | 典型用户、业务场景、什么时候该用 |
| 输入数据 | 是 | 文件类型、示例资料、建议数量、注意事项 |
| 处理过程 | 是，但去技术化 | 用“整理资料 / 识别关键对象 / 建立来源引用”等语言 |
| 输出能力 | 是 | 可问答、可浏览、可生成简报、可查看证据 |
| 成品样例 | 是 | 给用户看最终会得到什么 |
| 权限范围 | 是 | 个人、团队、公司 |
| 后台能力映射 | 否 | 只在代码/后台配置中存在 |

### 3.2 场景实例

场景实例是用户从模板创建出来的实际知识应用。

示例：

- “张磊的销售笔记 Wiki”
- “医疗行业客户关系库”
- “华东销售合同审阅场景”
- “客服中心售后知识助手”

实例字段：

- 来源模板
- 场景名称
- 创建人
- 可见范围
- 输入资料
- 处理任务
- 当前状态
- 可用能力：问答、浏览、生成成品、分享
- 默认问题建议
- 最近使用记录

### 3.3 处理任务

处理任务是前台和后台真正连接的桥。

用户从模板上传资料或选择数据源后，前台创建处理任务，后台执行资料整理、审核、入库和发布。前台只展示业务状态，不展示技术管道。

状态词：

| 状态 | 用户看到 | 可执行动作 |
|---|---|---|
| draft | 草稿 | 继续补充资料、删除 |
| submitted | 已提交 | 查看详情、撤回 |
| waiting_review | 等待管理员确认 | 查看等待原因 |
| processing | 资料处理中 | 查看进度 |
| needs_input | 需要补充资料 | 上传补充资料 |
| ready | 已可使用 | 打开场景、开始提问 |
| failed | 处理失败 | 查看原因、重试、联系管理员 |
| archived | 已归档 | 查看历史 |

### 3.4 知识空间对象

知识空间只展示用户能消费的结果：

- Wiki 条目
- 文档来源
- 客户/项目/组织对象
- 关系型答案归档
- 简报、审阅、问卷、制度答复等成品

知识空间不是后台数据源管理页。

## 4. 首页设计

首页只展示：

- 品牌和五项顶部导航。
- 中央大标题：`今天想问公司什么？`
- 一个高质量输入框。
- 一个主按钮：`问公司大脑`。

首页不展示：

- 场景卡片网格。
- 任务中心卡片。
- 运营指标。
- 待审核数量。
- 技术分类。
- 后台处理状态。

首页可以保留非常轻量的 placeholder 示例，但不做成独立卡片。例如：

`问制度、问客户、问项目、问自己创建的知识场景...`

## 5. 问公司大脑 Chat 体验重设计

当前 Chat 不能直接复用。它需要从“带很多面板的 demo 工作台”重做成正式产品级对话体验。

### 5.1 视觉原则

- 对话主区域优先，侧栏和证据区默认弱化。
- 画面干净，减少边框、徽章、色块和硬切分。
- 不使用大量彩色标签表达技术状态。
- 输入框始终是核心操作区。
- 答案区域像正式工作产物，不像调试日志。
- 证据、来源、任务动作按需展开，避免首屏噪音。

目标质感参考：

- ChatGPT / DeepSeek 的低噪音对话中心。
- Glean / Microsoft Copilot 的企业知识入口。
- NotebookLM 的来源驱动问答和资料消费心智。

### 5.2 页面结构

Chat 页面分为四个层级：

1. 顶部轻量栏：当前范围、场景切换、分享、历史入口。
2. 中央对话区：用户问题、公司大脑答案、追问。
3. 底部输入区：提问、上传、选择场景、输出要求。
4. 右侧抽屉：来源证据、任务画布、场景建议，默认不强占主视觉。

左侧固定大侧栏不作为默认形态。会话历史可以收进侧边抽屉或窄栏，避免塑料控制台感。

### 5.3 输入规则

输入框支持四类自然动作：

- 直接提问：`差旅报销标准是多少？`
- 指定对象：`帮我看 Northwind Labs 续约风险`
- 上传资料：`把这些 markdown 做成个人知识 Wiki`
- 指定输出：`整理成给销售总监看的简报`

用户不需要先选择技术引擎。系统按以下优先级决定范围：

1. 用户当前打开的场景实例。
2. 用户在问题中明确提到的场景或知识空间。
3. 用户有权限的最近使用场景。
4. 全公司默认可用知识来源。

### 5.4 答案结构

答案默认分三层：

1. 直接结论：先回答，不绕。
2. 依据摘要：用 2-4 条业务来源说明支撑。
3. 下一步动作：当问题适合变成任务或场景时出现。

示例：

```text
结论：Northwind Labs 续约风险偏高，但仍有扩容机会。

依据：
- 近 14 天无互动，续签窗口剩约 3 周。
- CTO 王皓近期提到扩建数据团队。
- 框架合同 ¥120 万仍在谈。

下一步：
[生成续约风险简报] [打开客户 360] [查看完整依据]
```

### 5.5 来源证据规则

来源默认收敛，点击后展开。不同来源使用业务名：

- 制度来源
- 合同来源
- 客户资料
- 项目记录
- 团队知识条目
- 上传资料
- 关系线索

来源展示不使用 `GraphRAG / NaiveRAG / embedding / chunk` 等词。关系类问题可以展示关系链，但默认不把大图谱塞到主答案里。

### 5.6 场景动作规则

Chat 中出现的场景动作必须来自模板或场景实例，不允许凭空出现。

动作类型：

- 创建新场景：从当前上传资料创建知识 Wiki。
- 使用已有场景：在“医疗行业客户关系库”中继续问。
- 生成成品：生成客户简报、合同审阅、制度答复。
- 沉淀模板：把当前任务保存为团队可复用场景。

动作出现时机：

- 用户问题需要多步输出。
- 用户上传了资料。
- 用户问的问题反复出现，可沉淀成场景。
- 答案涉及特定场景模板。

## 6. 场景模板页面设计

### 6.1 模板库列表

模板卡片必须展示：

- 名称
- 适用对象
- 需要输入的数据
- 得到的结果
- 创建耗时预期
- 是否需要管理员确认

卡片不展示技术方案名。

卡片 CTA：

- `查看模板`
- `用这个模板创建`

### 6.2 模板详情页

模板详情页结构固定：

1. 模板概览：一句话说明和适用场景。
2. 你需要准备什么：文件类型、资料示例、数量建议。
3. 系统会做什么：去技术化处理过程。
4. 创建后能做什么：问答、浏览、生成、分享。
5. 成品样例：展示真实输出形态。
6. 创建流程：上传资料、提交处理、等待就绪、开始使用。
7. 权限与发布：个人、团队、公司。

### 6.3 创建场景流程

创建场景不从空白表单开始，只能从模板或 Chat 动作进入。

流程：

1. 选择模板。
2. 命名场景。
3. 设置可见范围。
4. 上传资料或选择已有来源。
5. 确认资料清单。
6. 提交处理。
7. 进入任务中心查看进度。
8. 就绪后打开场景使用。

用户不需要配置技术参数。少量必要设置必须包装成业务语言，例如：

- 整理粒度：简洁 / 标准 / 详细。
- 取证范围：聚焦 / 平衡 / 全面。
- 关系识别方向：客户关系 / 项目关系 / 组织关系 / 供应链关系。

## 7. 内置官方模板清单

第一版建议内置 10 个模板。

### 7.1 个人知识 Wiki

- 适用：个人笔记、Markdown 文档、项目记录、学习资料。
- 输入：Markdown、TXT、PDF、网页摘录。
- 输出：可浏览 Wiki 条目、互链目录、来源引用、基于来源问答。
- 前台使用：浏览条目、在条目上追问、生成主题综述。
- 后台映射：知识沉淀型能力。

### 7.2 团队知识手册

- 适用：新人手册、项目复盘、销售 SOP、团队经验库。
- 输入：文档包、会议纪要、项目复盘、FAQ。
- 输出：结构化知识手册、章节目录、引用来源。
- 前台使用：浏览手册、按章节提问、分享给团队。
- 后台映射：知识沉淀型能力。

### 7.3 制度政策证据问答

- 适用：HR、财务、法务、行政制度查询。
- 输入：制度 PDF、流程文档、表格、公告。
- 输出：带依据的制度答复。
- 前台使用：问制度、查看原文依据、整理成可转发答复。
- 后台映射：文档证据型能力。

### 7.4 合同 Playbook 审阅

- 适用：销售合同、采购合同、框架协议审阅。
- 输入：合同文本、公司条款库、风险 playbook。
- 输出：风险条款、缺失条款、替换建议、审阅摘要。
- 前台使用：上传合同、生成审阅结果、分享给法务。
- 后台映射：文档证据型能力。

### 7.5 RFP / 安全问卷响应

- 适用：售前、安全、合规问卷。
- 输入：客户问卷、历史答案库、安全文档。
- 输出：批量答案草稿、待确认项、引用依据。
- 前台使用：导入问卷、生成答案、分配审核。
- 后台映射：文档证据型能力。

### 7.6 客户 360 简报

- 适用：销售会前准备、客户成功续约、客户画像。
- 输入：客户档案、会议记录、合同、项目记录。
- 输出：客户简报、风险信号、机会信号、下一步建议。
- 前台使用：输入客户名生成简报。
- 后台映射：关系知识型能力。

### 7.7 关系风险尽调

- 适用：投资尽调、供应商风险、客户风险、项目风险。
- 输入：报告、合同、表格、访谈记录、公开资料。
- 输出：关系链、风险清单、证据链、尽调报告。
- 前台使用：问风险、查关系链、生成尽调简报。
- 后台映射：关系知识型能力。

### 7.8 垂域关系知识库

- 适用：医疗、金融、制造、供应链等领域知识图谱式问答。
- 输入：领域 PDF、标准文档、病例/项目/供应链资料、表格。
- 输出：领域对象、关系线索、多跳问答、证据链。
- 前台使用：按领域问题提问，生成画像或分析报告。
- 后台映射：关系知识型能力，可由管理员选择领域识别规则。

### 7.9 智能客服知识代理

- 适用：帮助中心、订单售后、产品咨询。
- 输入：帮助文档、订单规则、售后流程、FAQ。
- 输出：客服问答组件、转人工建议、答案依据。
- 前台使用：嵌入式客服、客服模拟、答案审核。
- 后台映射：文档证据型 + 场景运行配置。

### 7.10 研究报告 / 学习指南

- 适用：市场研究、行业分析、内部学习资料。
- 输入：资料包、网页摘录、报告、会议纪要。
- 输出：研究报告、学习指南、摘要、引用。
- 前台使用：生成报告、改写成不同受众版本。
- 后台映射：知识沉淀型能力。

## 8. 我的场景

我的场景展示已创建实例，不展示模板。

列表维度：

- 场景名称
- 来源模板
- 状态
- 可见范围
- 最近使用
- 资料数量
- 可用动作：打开、继续处理、分享、管理

详情页结构：

- 场景说明
- 适用问题
- 已接入资料
- 处理状态
- 推荐问题
- 最近成品
- 权限和分享

## 9. 任务中心

任务中心分三类：

- 资料处理任务：上传资料后等待建库。
- 业务生成任务：Chat 中生成简报、审阅、问卷、报告。
- 审核发布任务：管理员确认、团队发布、失败重试。

任务卡片必须告诉用户：

- 这是什么任务。
- 为什么在这里。
- 现在处理到哪一步。
- 用户下一步能做什么。

## 10. 知识空间

知识空间用于消费已完成结果：

- Wiki 模式：适合个人知识 Wiki、团队知识手册。
- 文档证据模式：适合制度、合同、RFP。
- 关系对象模式：适合客户、项目、供应链、尽调。
- 成品归档模式：适合简报、报告、制度答复。

知识空间允许继续提问，但不是另一个 Chat 首页。它的定位是浏览和沉淀。

## 11. 前台到后台的数据契约

前台创建场景时，向后台提交：

```ts
type CreateScenarioRequest = {
  templateId: string;
  name: string;
  description: string;
  visibility: "private" | "team" | "company";
  sourceIds: string[];
  uploadedFiles: {
    name: string;
    type: string;
    size: number;
  }[];
  businessOptions: Record<string, string>;
};
```

后台返回处理任务：

```ts
type ProcessingTask = {
  id: string;
  scenarioId: string;
  status:
    | "draft"
    | "submitted"
    | "waiting_review"
    | "processing"
    | "needs_input"
    | "ready"
    | "failed";
  progress: number;
  currentStep: string;
  userMessage: string;
  nextActions: string[];
};
```

前台只展示 `userMessage` 和业务状态，不展示后台技术日志。

## 12. 文案规则

禁止词：

- RAG
- GraphRAG
- NaiveRAG
- LightRAG
- embedding
- chunk
- vector
- entity extraction
- prompt
- topK
- rerank

可用词：

- 知识来源
- 资料整理
- 来源引用
- 关系线索
- 关键对象
- 处理任务
- 已可使用
- 需要补充资料
- 适用场景
- 输入数据
- 输出结果

例子：

- 不说：“使用 LightRAG 抽取实体关系。”
- 改说：“系统会识别资料里的关键对象和它们之间的关系。”

- 不说：“上传文件后 chunk 并 embedding。”
- 改说：“系统会把资料整理成可引用的知识来源。”

## 13. 实现优先级

第一阶段：

- 首页极简化。
- 五项顶部导航。
- 场景模板库和模板详情页。
- 创建场景基础流程。
- 任务中心处理状态。
- Chat 视觉重设计第一版。

第二阶段：

- 我的场景详情。
- 知识空间多形态浏览。
- 任务中心失败重试和补资料。
- 成品分享和团队发布。

第三阶段：

- 与真实后端处理任务对接。
- 管理员审核流。
- 场景模板配置后台。
- 权限治理。

## 14. 验收标准

- 首页没有任务卡片和场景卡片，只保留问公司大脑。
- 顶部导航固定为五项，并且每项职责清晰。
- 用户能从模板详情页理解“适用情况 / 输入数据 / 输出效果”。
- 用户能从模板创建场景实例。
- 上传资料后进入任务中心，并看到业务化处理状态。
- 场景就绪后能从我的场景进入问答或浏览。
- Chat 页面视觉不再像三栏控制台，主对话体验干净、聚焦。
- Chat 答案能自然推荐模板动作，但不打断普通问答。
- 所有前台文案不暴露技术黑话。
