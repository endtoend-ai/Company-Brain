# FF-CompanyBrain 前台 Chat-First 重构设计

日期：2026-06-24

## 1. 目标

把前台从“场景应用工作台”改回用户更容易理解的“问公司大脑”正门。

用户进入前台后的第一反应必须是：我可以直接问公司问题。系统先回答并给依据；当问题适合进一步处理时，再把用户引导到客户简报、合同审阅、安全问卷、知识手册等场景任务。

这次重构不是删除场景能力，而是调整它的出现时机：场景从首页主入口降级为 Chat 答案后的下一步动作、任务中心里的持续工作流，以及场景库里的高级模板。

## 2. 当前问题

上一版 `/app` 把首页做成了“企业 RAG 场景应用平台”，有工作台、场景库、我的场景、创建场景、成品库等入口。它在能力覆盖上是完整的，但普通用户一进来会困惑：

- 不知道第一步该问问题、选场景，还是创建场景。
- 场景运行器像“填表后点击运行”的单轮流程，无法体现企业级任务闭环。
- Chatbot 被放到 `/app/chat`，从核心入口变成了角落能力。
- 分享、创建场景、官方模板、成品库等功能虽然都有，但缺少自然触发语境。

## 3. 核心决策

前台采用 Chat-First 结构：

1. `/app` 是全屏“问公司大脑”首页。
2. 用户输入问题后进入三栏 Chat 工作台。
3. Chat 工作台回答问题、展示证据，并根据问题推荐下一步动作。
4. 下一步动作打开右侧任务画布，而不是跳到孤立的单轮表单。
5. 任务画布支持补充输入、查看证据、生成草稿、追问修改、保存成品。
6. 场景库、创建场景、分享、我的场景、成品库全部保留，但从主入口能力变成二级能力和任务闭环的一部分。

## 4. 新信息架构

前台导航保留少量业务词：

- 问公司大脑：默认首页和主入口。
- 知识空间：浏览制度、客户、项目、文档、wiki 条目。
- 任务中心：查看和继续处理生成中的简报、审阅、问卷、手册。
- 场景库：官方模板和团队模板，作为高级入口。
- 我的：我的会话、收藏、成品、场景草稿。

不再把“创建场景”作为首页强主按钮。创建行为从两个自然位置进入：

- 从官方模板复制为团队场景。
- 从一次成功任务沉淀为可复用场景。

## 5. 首页设计

`/app` 首屏只做一件事：让用户问。

页面结构：

- 顶部品牌与轻导航。
- 中央大输入框：`今天想问公司什么？`
- 示例问题按业务意图展示：问制度、查客户、看项目、审合同。
- 次级入口收在下方或右上：知识空间、任务中心、场景库。

首页不展示运营指标、待审核数量、场景卡片大网格。那些信息属于任务中心或管理员后台，不适合作为员工前台正门。

## 6. Chat 工作台设计

Chat 工作台仍然使用三栏结构，但语义要调整：

- 左栏：会话历史、知识空间范围、常用任务入口。
- 中栏：问答流，包含用户问题、公司大脑答案、追问输入。
- 右栏：证据与任务画布。

答案必须包含：

- 直接结论。
- 关键依据。
- 来源列表。
- 可点击的下一步动作。

下一步动作示例：

- “生成续约风险简报”
- “打开客户 360”
- “整理成制度答复”
- “审阅这份合同”
- “生成安全问卷草稿”

这些动作来自场景模板，但用户不需要先理解模板。

## 7. 任务画布设计

任务画布是场景能力的新载体。它替代上一版“输入表单 + 点击运行 + 一次性结果”的运行器。

任务画布应包含：

- 任务标题和状态：草稿、生成中、待补充、待审核、已完成。
- 步骤列表：确认对象、收集证据、生成草稿、修改完善、保存成品。
- 当前步骤输入区：可补充客户名、文件、会议目标、输出格式等。
- 证据区：展示系统使用了哪些知识来源。
- 草稿区：可继续追问、重写、保存、分享。

任务画布不是另一个聊天框。它是一块可持续工作的业务产物编辑区。

## 8. 场景库和创建场景

场景库继续保留，但定位调整为“模板库”：

- 官方模板定义最佳实践。
- 团队模板沉淀真实业务流程。
- 用户可以从模板启动任务，也可以复制模板。

创建场景继续保留，但不作为普通用户第一步：

- 从模板复制时创建。
- 从任务成品沉淀时创建。
- 管理员或高级用户可以进入完整创建器。

创建器应避免从空白表单开始。默认展示“从当前任务生成”的配置，包括输入项、知识来源、输出格式、证据策略和可见范围。

## 9. 分享和成品

分享保留，但分享对象必须更具体：

- 分享一条带依据的答案。
- 分享一份任务成品，如客户简报、合同审阅结果、安全问卷草稿。
- 分享一个团队场景模板。

“成品库”改名为“任务中心”或并入任务中心。用户看到的是我正在处理和已经完成的业务成果，而不是抽象的 deliverable 列表。

## 10. 数据和组件边界

第一阶段仍使用 fixture，不接真实后端。

需要新增或调整的数据结构：

- `ChatSuggestion`：答案后的下一步动作。
- `TaskCanvas`：由场景模板实例化出来的任务。
- `TaskStep`：任务步骤、状态、输入和输出。
- `Artifact`：任务成品，可分享、保存、审核。
- `ScenarioTemplate`：官方和团队模板。

组件边界：

- `AskHome`：`/app` 的全屏问答首页。
- `ChatWorkspace`：升级后的三栏 Chat 主工作台。
- `EvidencePanel`：证据和来源展示。
- `ActionSuggestions`：答案后的下一步动作卡。
- `TaskCanvas`：右侧任务画布。
- `TaskCenter`：任务中心列表和详情。
- `ScenarioLibrary`：模板库。
- `ScenarioCreator`：从模板或任务沉淀场景。

## 11. 实现范围

本轮实现聚焦前台形态重构：

- 改造 `/app` 为问答首页。
- 将旧 `/app/chat` 能力升级为主 Chat 工作台。
- 在 Chat 答案后加入场景动作推荐。
- 加入右侧任务画布。
- 将现有场景库、创建场景、我的场景、成品库重新挂到二级路径。
- 保留现有 fixture 数据，但重命名和重组为用户可理解的任务模型。

暂不做：

- 真实后端接入。
- 权限系统改造。
- 真实文件上传和解析。
- 多人协作编辑。

## 12. 验收标准

- 用户打开 `/app` 后第一眼知道可以直接提问。
- Chatbot 是前台核心，不是二级角落入口。
- 用户问完一个客户、合同或制度问题后，能看到自然的下一步动作。
- 点击下一步动作后进入多步任务画布，而不是单轮结果页。
- 场景库、创建场景、分享、任务成品都还在，但不会干扰首次使用路径。
- 构建通过，主要路由返回 200。
- 桌面和窄屏下首页、Chat 工作台、任务画布没有明显内容重叠。
